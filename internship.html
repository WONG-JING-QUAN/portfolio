During the practicum at Rhee Analytics Sdn. Bhd. as a Data Analyst Intern, the project focuses on insider disclosure data from the Singapore Exchange. When directors, chief executive officers and substantial shareholders of SGX-listed companies change their shareholdings, they are required to file disclosure forms, which are published as PDF announcements on the SGX website. These filings contain useful information such as the reporting person, transaction date, number of shares, price and change in ownership, which can indicate how insiders view their company. However, this information is spread across thousands of individual PDF documents and cannot be analysed directly.

Therefore, this project aims to develop an automated end-to-end data pipeline that collects, extracts, validates and processes SGX insider disclosure data, together with an Excel-based stock screener that presents the processed data for fast filtering and analysis. The project is intended to reduce repetitive manual work, improve the accuracy and consistency of the data, and provide a practical decision-support tool for analysing listed companies based on insider activity, share buy-backs and market data.

Read the full problem statement

The previous process of collecting and preparing SGX insider disclosure data required a large amount of manual effort. Disclosure files had to be downloaded and checked individually, and the scripts had to be launched manually. An audit of 49,632 PDF files in the processed archive identified 39,516 unique submissions, of which only 10,114 had both the DI and DIb versions, while 29,356 had only the DIb version and 46 had only the DI version. Many DI files were XFA dynamic forms that displayed only a “Please wait” message and could not be read by normal PDF text extraction. This made it difficult to confirm whether the archive was complete and which file version should be used.

The extraction of data from the filings was also difficult because the forms use inconsistent layouts and contain checkboxes, multiple shareholders and multiple transaction tables. Errors at this stage often did not stop the program, but instead produced output that looked reasonable but was wrong. For example, one checkbox option describing a corporate action had never been captured in more than 5,000 historical rows, because its tick mark was lost during the PDF-to-text conversion. Other silent problems included dates whose day and month were swapped by Excel, ticker codes such as 5E2 being converted into scientific notation, and duplicate or missing files.

In addition, the existing Excel stock screener was difficult to maintain, as it was driven by a single formula of about 4,000 characters that was close to the Excel formula length limit. Adding or changing a filter required editing this long formula, and some filters returned incorrect results.

Therefore, an automated and validated data pipeline is required to collect and process SGX insider disclosure data with minimal manual intervention, together with a modular stock screener that is easy to use and maintain. This project develops such a solution so that updated data can flow from the SGX website to the screener with consistent quality.

Methodology

The project follows an end-to-end workflow of eight stages, as shown in Figure 1. In the first stage, Python scripts using Selenium and Requests access the SGX website and download the insider disclosure PDFs, share buy-back notices, daily prices and the SGX stock screener list. The raw files are saved with consistent file names in an organised folder structure. In the second stage, the scripts are automated using batch (.bat) launchers, configuration files, daily log files and Windows Task Scheduler, so that they run unattended every weeknight from Monday to Friday.

In the third stage, an identifier script converts each filing into text, selects the DI (XFA) or DIb version, keeps the original layout, recovers ticked checkboxes and detects the form type, so that each file is routed to the correct extractor. In the fourth stage, separate extractors capture the required fields from Forms 1, 3, 5 and 6, such as holdings before and after the transaction, transaction dates, number of shares and prices, into one shared structure, including filings with multiple shareholders. The results are saved as long and short insider CSV files.

In the fifth stage, the extracted data is validated by comparing it field by field with the original SGX filings, while an audit script flags missing or blank fields for review and all issues are recorded in log files. Every correction is regression-tested on real sample filings so that records that were already correct are not affected. In the sixth stage, Power Query cleans the column headers, assigns the correct data types, keeps dates in DD/MM/YYYY format and joins the price, company, share buy-back and insider data by ticker code into one master table for the screener.

In the seventh stage, the long screener formula is broken into modular named LAMBDA formulas, with one formula for each filter, so that filters can be added or removed easily, while VBA is used for date entry and buttons. In the final stage, the Excel stock screener allows users to filter, search and sort stocks, shows a live count of matching stocks and displays the insider and share buy-back dates for each stock.

Each filter in the screener will be tested against expected results to confirm that the screener output is correct. Together, these stages connect the SGX website to the final screener, so that updated data can be collected, checked and screened with minimal manual work.

Background of the study

Insider disclosure data is an important source of information in equity research. In Singapore, the interests of directors, chief executive officers and substantial shareholders are reported through standard notification forms, mainly Form 1, Form 3, Form 5 and Form 6. For example, Form 1 is filed by directors and chief executive officers, while Form 3 is filed by substantial shareholders. Each filing records the company, the reporting person, the type of transaction, the number of shares held before and after the transaction, the consideration paid and the circumstances that gave rise to the change in interest.

At Rhee Analytics Sdn. Bhd., this data is collected from the SGX announcement portal and combined with other SGX datasets, such as share buy-back (repurchase) announcements, daily security prices and the SGX stock screener company list. Each filing may be published in two PDF versions: a dynamic XFA form (DI) that can only be displayed properly in Adobe Reader, and a static version (DIb) that can be read in a web browser. The layouts of the four forms are also different, and a single filing may contain several shareholders, several transactions and many checkbox selections.

This project focuses on building an automated workflow using Python, pandas, pypdf, pdfplumber, Selenium, Power Query, Excel formulas and VBA. The workflow will scrape the filings, convert them into text, extract the required fields into a standard structure, validate the results, merge them with market data and present them through an interactive Excel stock screener.

Scope of the study

This project focuses on the automation of data collection, extraction, validation, processing and screening of SGX insider disclosure data at Rhee Analytics Sdn. Bhd.

The main data sources are the insider disclosure filings (Forms 1, 3, 5 and 6) published on the SGX website, together with SGX share buy-back announcements, daily security prices and the SGX stock screener company list. The project covers both current filings and historical records, which are kept in separate current and historical output folders.

The project covers the development of Python scripts for web scraping, PDF-to-text conversion and form extraction; validation and audit scripts; and Windows batch files with Task Scheduler for automated nightly runs. It also covers an Excel stock screener that uses Power Query to build the master table, named LAMBDA formulas for the filter engine, and VBA for buttons, date entry and data refresh. Supporting configuration files and README documentation are also included.

The project focuses on preparing reliable data and providing a screening tool. It does not change the SGX source data and does not automatically make investment or trading decisions. Instead, the screener output supports analysts in reviewing insider activity and making their own investment decisions. Similar data tasks for HKEX and United States market data carried out during the internship are treated as related work and are not the main focus of this proposal.

Expected findings

The project is expected to greatly reduce the manual work required to collect and prepare SGX insider disclosure data. Once the scripts are scheduled, new filings, share buy-back notices and prices are expected to be downloaded, extracted and processed automatically every weeknight, with log files recording the result of each run.

The project is also expected to produce a complete and validated insider disclosure dataset. The file audit, the field-by-field comparison with the source filings and the regression testing are expected to detect missing files, extraction errors and silent data problems before they reach the users.

Overall, the modular Excel stock screener is expected to make it easier and faster for users to filter SGX-listed companies by insider activity, share buy-backs, price and sector, and to maintain the screener when new filters are needed. The project is expected to improve the efficiency, accuracy and consistency of the data workflow while providing useful information to support data-driven investment decision-making at Rhee Analytics Sdn. Bhd. and its affiliated asset management company.

SGX insider data: collecting the filings and extracting them

Objective 1 Objective 2

Tasks Completed

I reported for duty at Rhee Analytics on Monday, 3 August, and was introduced to the main project I would be working on: a data pipeline for SGX insider filings. These are the forms that directors, CEOs and major shareholders of Singapore-listed companies must submit whenever their shareholdings change (Forms 1, 3, 5 and 6), which are published on the SGX company announcements page (Singapore Exchange, n.d.-a). The company already had a script that downloads these filings as PDFs, but everything after that, from reading the forms to producing clean tables, had to be built from scratch.

I started with the download script because nothing else would work without reliable raw files. I tidied it into proper folders, put all the folder paths into one settings file so the project can be moved to another PC easily, and set it to run by itself every weeknight using Windows Task Scheduler. Next, I checked the PDF archive. Each filing can come in two versions, an interactive XFA form (DI) and a normal PDF (DIb), and I wanted to know how complete our archive really was. The 49,632 PDFs turned out to be 39,516 unique filings. Only about a quarter of them had both versions, most had only the normal PDF, a small number had only the XFA version, and a few hundred were exact duplicates. I put the results into an Excel report so the team could see the gaps clearly.

With the raw files sorted out, I worked on turning the PDFs into text and then into tables. I changed the text conversion so it keeps the original page layout, and I designed one common 46-column table format for all four forms so that current and historical data look the same. After each change, I opened the original PDF filings and compared them field by field with the extracted tables, using real examples of every form type, to make sure each value matched. Towards the end of the week I also started on a smaller side task, extracting key accounting figures such as revenue and profit from Hong Kong results announcements.

Skills Applied or Developed

This week I mainly used Python (Selenium for downloading, pdfplumber for reading PDFs and pandas for building tables). I also learned how to schedule scripts in Windows Task Scheduler and how to keep settings in a separate configuration file instead of writing them inside the code.

Challenges and How I Addressed Them

The first problem was that many XFA files only show a “Please wait” message when opened in a browser, so normal PDF tools could not read them at all. I wrote a check to detect this message and separate those files, and then used file sizes and names to tell genuinely missing files apart from duplicates.

The second problem took longer to notice. Some ticked checkboxes in the forms were disappearing during the PDF-to-text conversion, so the extractor recorded them as not selected. One filing with four shareholders was treated as a single-shareholder filing for this reason, and one checkbox option had never been captured in the whole history. Instead of relying on the tick symbol, I made the extractor read the structure of the form, such as which sections are filled in, and this fixed both cases.

Key Learning / Takeaway / New Insights

My biggest takeaway this week was that converting a PDF to text can quietly lose information. A missing tick mark does not always mean the box was not ticked. I also realised that before building anything clever, it is worth checking whether the raw data is complete, because every later step depends on it.

When matching company names to tickers, the script sometimes picked the wrong company, for example Keppel REIT instead of Keppel Corporation. I made it confirm every match against the official SGX securities list before accepting it.

Key Learning / Takeaway / New Insights

I learned that a script can be completely correct and still fail because of when and where it runs. For scheduled jobs, the computer and network environment are just as important as the code. Good logging made this problem possible to investigate.

04 — Key Terms

The vocabulary of the work.

Terms used throughout the weekly reports.

SGX / HKEX
Singapore Exchange and Hong Kong Exchanges and Clearing, the two stock exchanges whose data I worked with most.
Insider filing (Forms 1, 3, 5, 6)
A form that directors, CEOs and major shareholders of SGX-listed companies must file when their shareholding changes.
DI and DIb
The two versions of each SGX filing: DI is an interactive XFA form that needs Adobe Reader; DIb is a normal PDF.
Data pipeline
A chain of scripts that collects raw data, cleans it, checks it and produces a ready-to-use table, usually without manual work.
Scraper
A script that collects data from a website automatically.
Stock screener
An Excel tool that lets users filter and sort listed companies by conditions such as price, sector or insider activity.
CCASS
Hong Kong’s Central Clearing and Settlement System, which records how many shares are held.
SAS
A statistical software package the company used before for its HKEX reports; its licence has expired. The SGX pipeline does not use SAS.
Python / DuckDB
Python is the programming language I used for most scripts; DuckDB is a fast database used to run SQL queries on CSV files.
Power Query / LAMBDA / VBA
Excel tools: Power Query loads and cleans data, LAMBDA creates reusable named formulas, and VBA runs macros and buttons.
Task Scheduler
The Windows tool that runs scripts automatically at set times, for example every weeknight.
API
A web address that returns data in a machine-readable format, used instead of reading the web page.
Regression test
Comparing the output before and after a change to make sure nothing that already worked was broken.
